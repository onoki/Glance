# Title Enter safety regression

October 8, 2026 feedback: Enter at the beginning of a title in Next week inserted a blank task but the populated task disappeared. Undo recovered it. Normal browser trials with the first and second rows, with and without subcontent, did not reproduce the exact disappearance or a move to today. The investigation found two concrete hazards in that code path.

Previously, start-title Enter used the middle-title split path. It cleared and saved the original title/subcontent while independently requesting creation of a replacement containing the complete original document. The mounted-component regression reproduces the original becoming blank while creation is stalled. A creation failure could therefore leave its text absent from the saved list, and the rejection was not handled. This was a reproducible data-loss path, not proof of which request failed in the reported incident.

Dashboard creation also used `positionOverride || Date.now()`. A legitimate midpoint of zero was replaced with a timestamp, placing the populated replacement at the end of its column instead of adjacent to the original blank row. That can look like disappearance when the bottom is outside the viewport. This does not change the scheduled date. The regression uses negative/zero positions and asserts the exact midpoint.

Start-title Enter now creates only a blank row above. The original row never needs a text or metadata write for that operation. Its caret remains at title position one. Adjacent creation waits for pending edits, resolves the current row, preserves the scheduled date and uses neighbours within the source weekday when This week is grouped. Undo/Redo share the structural action queue, including an Undo requested while creation is pending.

Middle/selected-title Enter still splits the text and carries subcontent to the new task. It now saves the destination first, then shortens the source through its save owner. Creation failure leaves the original untouched. If the source changes during creation, the old snapshot cannot overwrite it; the completed copy remains available with an explanatory error. If the source save fails after creation, the durable original and suffix copy preserve the data and the existing save-error UI remains actionable. The full local source is restored too, preserving any intervening edits: a retry followed by Undo must never save a shortened source and then delete its only suffix copy. History records only the completed creation for an incomplete split, or both documents for a completed split. People has corresponding split Undo/Redo support.

`ui/tests/titleEnterSafety.test.js` mounts real TaskItem save owners and invokes the real key handler with ProseMirror selections against the actual Dashboard/People list models and a controlled, revision-checking transport. Sixteen category/row combinations cover Next week, This week, old weeks, Notes, No date, Uncategorized, New tasks and People. Cases include first/second rows, interleaved weekday positions, rich titles, links, hard breaks, nested/image/blank subcontent, repeated Enter, pending edits, delayed and failed creation, failed source writes, blocked Undo and retry, middle/ranged selections, typing during creation, schema-default attributes and Undo/Redo. Browser checks also verify native keyboard handling, persisted source identity/date, and retained subcontent in Dashboard and People. Test data is disposable; production notes are not used.

## Follow-up audit and fixes

The follow-up audit independently reproduced four adjacent risks. The original diagnostic (`artifacts/task-safety-audit.mjs`) recorded the unsafe behavior; it is historical evidence, not a passing regression suite. All four paths are now covered by `ui/tests/taskSafety.test.js` and the shared history failure tests.

- Outermost Shift+Tab promotion uses the same queued, destination-first operation as title splitting. The editor no longer shortens itself immediately. TaskItem owns the guarded source commit, awaits creation and saving, blocks repeated promotion, and restores complete local content after a failed shortening save. Typing during creation retains the newer source plus the completed copy. Successful promotion is one recoverable split in both Dashboard and People, including caret, rich marks, nested/image content and intentional blank bullets.
- Dashboard and People structural history use `taskHistory.js`. It validates expected rich documents and metadata against fresh server rows before writing; restores or updates every retained destination before deleting any source/copy; and revision-checks writes and deletions. Failures are reported and retain the history entry. Retry accepts an already-applied target snapshot, including after a lost response, instead of replaying or overwriting arbitrary newer content. Restoring a soft-deleted row preserves its saved content; an unexpected restored version is left visible for review rather than replaced. A missing/purged row reports a recovery error rather than silently creating a replacement identity. Retained destinations are checked again before copies are retired.
- Ordinary task deletion settles pending saves and sends the revision of the selected document in both views. People boundary merges now do the same. Joins record their history before retiring the source, so a failed or lost deletion response remains recoverable. Failed ordinary text saves do not create successful Dashboard edit-history entries. Real revision conflicts remain errors; no conflict bypass was added.
- Title emptiness is structural, so image-only titles are never mistaken for empty tasks by Backspace/Delete.

The safety suites use strict controlled transports and real TaskItem save owners/list models, without production notes. They include successful operations, delayed/failed creation, failed source and history writes, concurrent source edits, partial retries, lost responses, and Undo/Redo. These focused checks complement the existing nested-list, repeated-Tab, title Enter and clipboard regressions; they do not claim every possible concurrency interleaving is transactional across multiple tasks.
