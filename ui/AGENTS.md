# Typography and controls

- Use bundled IBM Plex Sans, unmodified under SIL OFL 1.1, in every tab including Settings. Keep its attribution, source information and license in `assets/fonts/`; do not reintroduce the retired bitmap font.
- Both bundled upright and italic variable faces support weights 100–700. Genuine bold/italic task formatting, including Ctrl+B/Ctrl+I and existing saved marks, is supported. Disable font synthesis everywhere; do not strip formatting or silently substitute another font. UI controls and selected navigation remain regular 400 so selection cannot alter widths. Section/column/person/date headings use genuine 600 at the same size; Settings subsection headings use 500. Prefer fill, borders and hierarchy for emphasis, without extra spacing.
- The user chose 7 CSS px after comparing fonts at different sizes. Use shared 7px body, title and metadata tokens and 1.35 line height in every view. Keep the existing 16px minimum control targets and checkbox/title center alignment. IBM Plex Sans is an outline font, with no native bitmap grid; do not impose BigBlue's old 8×12 assumptions.
- The accepted Notepad palette uses #fafafa app/header, #ffffff panels, #1a1a1a ordinary text, #5a5a5a secondary text, #cccccc borders, #e5e5e5 selected tabs and #202020 focus/link accents. Ordinary surfaces and controls stay neutral. Preserve semantic tag, highlight, warning, drag and danger colors; distinguish selected tabs with fill/border without inverting their text.
- Shared controls have neutral, emphasized, and danger variants in `src/styles/controls.css`. Keep shared appearance and the documented heading hierarchy in `src/styles/surfaces.css`; avoid ad hoc component font, weight, padding, or selected-state overrides. Keep the dashed empty-editor insertion target distinct.
- Ordinary unpressed controls and task text use the dark neutral `--text-main` color consistently, with no alternating row colors. Links stay underlined in the neutral accent; preserve meaningful highlight, completed-task, selected-control, and danger colors. Navigation buttons and the Settings/New window icons share a 1px gap defined in `controls.css`.
- Task action bars appear only while focus is within that task (including its action controls), never on row hover. They must not reserve row height or shift text. On window blur, dismiss the bar and all menus and remove them from hit testing. Restored focus alone must not reopen them. A click on a task may reveal its bar after the click target has been resolved (in the bubbling click handler, never pointerdown or focusin), including the first click back into Glance. Other tasks and previously open menus stay dismissed. Editing keystrokes may also restore the focused task bar.
- Preserve the 7px base font size. Do not reinstate automatic text-origin correction: its measurement/write feedback can oscillate after zoom or DPI changes. Keep grayscale rendering. Zoom uses practical intermediate steps, a reset, and an explained asterisk when the 7px text size maps near whole device pixels; alignment does not guarantee sharpness or eliminate antialiasing. Keep `BASE_FONT_SIZE` in `zoom.js` synchronized with the CSS size. Desktop zoom preferences belong to the current PC and monitor, not the portable database. Avoid transformed text containers.
- Keep task columns compact but provide a 64px blank insertion tail. Follow the active caret near viewport edges without snapping earlier edits to the list end.
- Task menus require deliberate click/keyboard activation, never hover. Keep Move versus Send a copy explicit. Undo notifications must target the announced operation, never a later edit.
- The Windows desktop host requests grayscale text antialiasing (`--disable-lcd-text`) before creating WebView2 windows. This removes LCD color fringes rather than all smoothing; do not claim CSS `font-smooth` disables smoothing on Windows or change system-wide settings.
- Keep + Person neutral like Rename/Archive. Person switches commit the selected person and fetched rows together and must not animate outgoing/incoming people as task reorders.
- The focus outline must connect the full-width action bar to the left task edge; hide both lines with dismissed controls or during dragging. Empty-task Delete focuses the following title at position 1; Backspace retains backward focus.
- Explicit task focus requests after editing must resume that destination's dismissed controls and remeasure the toolbar after layout. Native focus restoration remains insufficient. Focused rows must not transform their fixed-position toolbar during list movement.
- Backspace title merging uses the preceding visible task within the current Dashboard category, including weekday grouping order; never the global interleaved mainTasks array. The first row cannot merge across columns.

- Boundary Delete/Backspace joins logical lines, not just task titles. Use `taskJoin.js` for shared rich-document transformations. Forward Delete consumes the first subcontent line before the next task; cross-task joins append the lower title to the upper task's final subcontent paragraph (or title if there is no subcontent). Preserve caret position, nesting, remaining lines, and rich marks. Keep joins within the current column/person and recoverable with Undo.

- Plain Left/Right cross exact collapsed editor boundaries within the current column/person, including title/subcontent; preserve modified arrows and selections. Do not create a task at the last Right boundary.

- Up/Down navigation must never create tasks or cross Dashboard columns. At editor boundaries, Down enters the first subcontent paragraph at its end; Up from its first visual line returns to the title end. Leave wrapped-line navigation, selections and modified arrows native. The whole insertion tail darkens slightly on hover.

- Cross-task Up/Down preserve beginning/end caret intent; an empty source counts as beginning. Middle positions preserve screen X as closely as possible on the destination visual line. Helper windows use a slightly darker neutral top bar and plain Helper window label without a border or background; keep task surfaces and typography unchanged.

- Enter at the end of a title with existing subcontent prepends an empty bullet and focuses it. Preserve title-only task creation and middle-title splitting. People scrollbars belong at the window edge; the task content can retain a narrower readable width. Use the single shared ProseMirror typography rule for plain titles and subcontent.

- This week must expose today through Sunday even when empty, retaining past groups only with visible tasks. Never automatically redate unfinished tasks. Use categoryPickerDays for compact This week/Next week Move rows and planningWeekDays for column day targets; disable past assignments, stop day-drop propagation, and preserve Undo and task focus.

- Empty nested-list deletion must use scoped ProseMirror transactions, never whole-document setContent based on a local list child count. Only the sole outer list can qualify as the entire subcontent. Preserve parents, siblings, rich marks and populated descendants; use a resolved text selection and retain native Undo/Redo. Enter may exit only the final outer list. Keep nestedListSafety.test.js and task-key-handler regressions covering these boundaries.

- Keep compact Mo-Su rows immediately below This week and Next week without duplicate headings. Creating an adjacent task via Enter, title split, or subcontent promotion inherits the source scheduled date; explicit moves and independent additions retain their own scheduling rules.

- Removing an empty bullet with Backspace places the caret at the preceding text line end, falling forward only when no preceding line exists. All button hover selectors must exclude :disabled; retain disabled appearance and tooltips.

- Tab/Shift+Tab restructuring preserves intentional blank bullets on both sides, including blank-only lists. Whole-task Tab demotes the former title as an outer bullet with its existing subcontent nested underneath it, increasing every descendant's level by one. Outermost Shift+Tab promotes that title and lifts its children into the new task's subcontent, reversing the hierarchy; nested Shift+Tab remains a one-level list lift. Keep Dashboard/People parity and roundtrip tests with rich content, blank bullets and Undo/Redo. Blur must not delete content. Tab merges flush pending saves before reading snapshots and serialize across the list; use current visible neighbours within the same category/person. Carry acknowledged save revisions into retained dirty snapshots; never bypass real conflict checks. Retire a merged source through recoverable deletion so Undo preserves its identity.

- This week column headings use full weekday names; the Move picker remains compact Mo-Su. Every column can maximize below the top navigation and restore without losing widths or the normal horizontal viewport. Restore the regular view if its maximized category disappears or source navigation must reveal a task in another column.
- Send/Tags menus are multi-select: clicking a label toggles its checkbox and keeps the menu open; outside clicks and Escape dismiss it. Exclude labels, task bars and floating menus from Dashboard background panning. Preserve focus during Send label clicks so its focus-only toolbar stays available.
- Image display and handle resizing must never exceed loaded intrinsic dimensions. Fit large images to the container, preserve aspect ratio and smaller saved sizes, and bound legacy oversized widths on load without rewriting unrelated text. Whole-task drags use their own MIME type and capture handlers to bypass rich-text drop cursors; indicate only before/after a whole task using its midpoint. Preserve targets across child paragraph events and calculate weekday neighbours within the target day. Flush pending saves before drag metadata writes and let People editors acknowledge the resulting revision before further edits.
- History activity defaults expanded when populated, omits empty charts, and remembers the user's disclosure choice in local UI preferences. Move completed includes today's Dashboard and People notes, retaining person attribution and restoration to the original list. Flush pending edits first; never archive open or deleted notes.

- Enter at the start of a populated title inserts an empty task above without clearing/copying the original. Keep its identity, metadata, scheduled date, complete rich subcontent and caret. Adjacent creation and title splitting share the list's structural Undo queue; settle pending saves first. Middle/selected-title splits must persist the destination before shortening the source, report partial failures, and guard against typing during creation. Undo of an incomplete split may remove its copy but must not replace the source. Restore complete local source text if its shortening save fails, so retry plus Undo cannot discard the only suffix copy. Compare editing snapshots to the original model representation, accounting for harmless editor-added default attributes. Zero is a valid ordering position: use nullish fallbacks, never truthiness. Creation within This week and Next week uses neighbours from the same scheduled day. Keep `titleEnterSafety.test.js` covering these rules in Dashboard and People.

- Outermost Shift+Tab promotion is destination-first, queued and awaited, with the TaskItem save owner committing the guarded source only after creation succeeds. Never clear the RichTextEditor independently. Preserve full local content on a failed shortening save and keep partial-copy Undo from replacing a later source edit.
- Structural history in Dashboard and People shares `taskHistory.js`: validate fresh expected documents/metadata, restore/write retained destinations before source deletion, guard all writes/deletions by revision, report failures, and retain retryable history. Never swallow write errors as successful Undo/Redo or silently recreate a missing identity. Joins retain history before source retirement; failed ordinary saves must not enter successful edit history. Delete settles pending saves and checks the exact selected revision. Image atoms make titles nonempty. Keep taskSafety/history failure regressions covering these paths.
- This week and Next week always expose planning day groups. Next week shows all seven full weekday names with dates and supports day additions, drops, date-inheriting Enter and visual-order navigation. Use categoryWeekGroups/planningWeekDays for columns and categoryPickerDays for both compact Move rows. Empty day targets show the same red insertion line as task targets during whole-task drags, with no layout shift; clear it on exit/drop/cancel and do not show it for text/image drags. Maximize uses two outward diagonal arrows; restore uses inward arrows, both with accessible labels.
- In two weeks is a derived, optional column immediately after Next week and a Move menu option. Schedule its tasks for relativeWeekStart(2), preserving text and Undo; do not introduce a database category or automatic rescheduling. As time passes the unchanged scheduled date naturally moves the task into Next week and This week. There is no extra weekday picker for this postponement category.
- Planning-day background drops are delegated at the column capture phase. Everything before the next weekday heading text (margins, flex gaps and leading header whitespace) belongs to the preceding day. Resolve hover and drop with the same weekdayDropTarget helper; stop propagation so defaults cannot move the task to Monday. Skip task rows to preserve their own before/after targets, and ignore text/image drags. Keep the boundary regression in viewControls.test.js covering every adjacent day.

- Main navigation is Dashboard, People, Search, History with Alt+1–4 (including while editing). Exclude Ctrl/Meta/Shift, AltGr and composition; route through selectTab so recovery/clipboard guards remain effective. Search must focus its input on entry and reselection while retaining results.
- The retired Status Updates feature has no tab, marker actions or Ctrl+7 shortcut. Preserve old serialized document metadata and database/report data for backup, restore and export compatibility; do not restore active report or Office/authentication code.
- People name filtering hides nonmatching active tabs without changing selected notes or creating tasks. Esc clears and Enter deliberately selects the first match. Search-result navigation clears the filter to expose the target person. Creation dates use the existing createdAt and the focus-only task bar.
- Pending-save dots are absolute overlays inside a permanent narrow title gutter. Dirty/saving/clean changes must not alter editor width, wrapping, row height or click targets. All column maximize/restore controls, including New tasks, align right.
- Person-to-person Send uses the shared independent-copy API and audit marker. Resolve direct/tag recipients once, omit the source person and archived recipients, identify the source person on copies, and flush edits before copying. Keep navigationUsability.test.js and person-sending regressions.

- Leading blank bullet boundaries use removeBlankBulletBoundary before generic joins: Delete removes only the blank current leaf and Backspace at the next start removes only its blank preceding sibling. Preserve populated descendants, marks, selections, caret and native Undo/Redo; never broaden blank detection to parents with children. Cover both list kinds and multiple depths in nestedListSafety.test.js.
- Use one Send a copy menu. People places the Dashboard checkbox before people/tags and submits includeDashboard in the same batch. Keep explicit Send outside the scrolling recipient body, retain selections on failure and flush edits before copying.
- Source navigation holds its highlight for five seconds before a short fade. Link activation must snapshot href before editor focus can reflow compact URLs, cancel native anchor defaults (click, middle click and keyboard), and invoke the validated external opener before focusing. Background drops cannot navigate the app; do not break editor text/image drops. Keep externalLinkActivation.test.js.
- Never rewrite completedAt to archive a note. historyArchivedAt is independent; the 180-local-day chart counts all nondeleted completions regardless of archive state. Manual Move completed archives today, automatic day rollover archives only previous days, and unchecking clears both fields. Midnight/focus/visibility recovery must coalesce requests, settle saves, retry failures and use the offset at the relevant local midnight, including DST. Keep dayRollover.test.js and HistoryPrivacyTests.
- isPrivate is durable, false by default and preserved by partial updates. usePrivacy is per-window presentation, ON each launch: flagged bodies are invisible/inert/aria-hidden while unfocused, retain height, reveal with deliberate task focus, and conceal on task/window blur. Native window focus restoration alone cannot reveal. Apply the shared TaskItem in Dashboard, People, Search and History; never leak private text through snippets or hover UI. Sent/recurring/clipboard/split copies inherit privacy; joins OR flags; guarded Undo restores flags. The global header lock affects only this window’s presentation. This is screen privacy, not encryption: do not remove full text/media from API, clipboard, backups or export. Portable JSON carries flags and archive timestamps; offline HTML uses collapsed private disclosures. Keep privacy.test.js, TaskItem lifecycle, clipboard, send, recurrence and portability regressions.

- The font-comparison visual style is shared through surfaces.css: sentence-case 600-weight headings, 500-weight Settings subheadings, restrained 3px control/menu radii (2px for task tools/fields), white task surfaces, soft #e3e3e3 structural separators, and pale selected tabs with an inset bottom rule. Preserve the Notepad palette, helper distinction, 7px task font and 1.35 line height; no extra padding, row gaps, header height or transformed text. Ordinary/selected controls remain 400. Keep button dimensions stable across states and hover disabled controls unchanged.
- Focus ownership uses a 2px left pseudo-element and the existing 1px full-width toolbar line, outside layout. Keep the 10px visible completion box centered within its unchanged 12px hit area and on the first title line. All task lists share 1px vertical row padding and 12px subcontent indent per level; do not restore the former 27px indent or extra read-only row padding. Narrow windows retain zero outer content padding and compact wrapped navigation. Verify actual layout/focus states in all tabs using isolated data; avoid tests that mirror CSS declarations.
